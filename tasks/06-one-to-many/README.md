# Тема 6: @OneToMany (Category → products)

## Чему учит тема
- «Одна» сторона владеет КОЛЛЕКЦИЕЙ, а не ключом: `mappedBy` + навигация `category.getProducts()`; FK всё равно живёт в `products`.
- `cascade = ALL` и `orphanRemoval`: что сохраняется/удаляется вместе с родителем и что это значит на уровне SQL.
- LAZY-коллекции, устаревшие (stale) представления коллекции в первом уровне кэша, двунаправленная консистентность («обратная ссылка обязательна»).
- Производительность каскадных INSERT-ов и порядок удаления «дети → родитель».

## Как проверить задание
1. Методы репозиториев добавляйте только если задание явно требует (большинство решается через `EntityManager` и существующие методы).
2. Создайте тест-класс `OneToManyTask01Test` … `OneToManyTask10Test` в `src/test/java/com/example/jpalab/repository/`. Обычные сценарии — `@DataJpaTest`; TASK-10 — `@SpringBootTest` + `TransactionTemplate`.
3. Запустите: `mvn -Dtest=OneToManyTask01Test test` (замените имя).
4. Задание выполнено, если тест зелёный и выполнен «Критерий приёмки» (поведение + фрагменты SQL-лога/исключения, где требуется).
