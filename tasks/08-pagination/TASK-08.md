# Задание 08. Нестабильный порядок: тай-брейк по уникальному ключу
- Тема: Пагинация (Page / Slice / Pageable / Sort)
- Difficulty: 8
- Что нужно сделать: Добавьте в `ProductRepository` метод `Page<Product> findByPriceBetween(@Param("from") BigDecimal from, @Param("to") BigDecimal to, Pageable pageable)` — товары с ценой в диапазоне `[from, to]` (обе границы включены), страницей. Заранее созданный тест (TASK08Test) на данных с РАЗВЫМИ ПАРАМИ цен (10.00 × 2, 20.00 × 2, плюс 5.00 и 25.00 вне диапазона) запрашивает страницы `size = 2` с сортировкой (а) только по цене и (б) по цене + id: вариант (б) даёт ТОЧНО детерминированное разбиение (проверяется точный порядок id и повторным вызовом); для варианта (а) в комментарии зафиксирован риск «прыгающих» элементов.
- Стартовый код:
```java
// com/example/jpalab/repository/ProductRepository.java

// TODO: @Query (JPQL) — p.price BETWEEN :from AND :to
Page<Product> findByPriceBetween(@Param("from") BigDecimal from,
                                 @Param("to") BigDecimal to, Pageable pageable);
```
- Тест для проверки:
```bash
mvn -Dtest=com.example.jpalab.tasks.t08.TASK08Test#uniqueTieBreakerMakesPagingDeterministic
```
- Критерий приёмки: Тест: 6 товаров (5.00, 10.00, 10.00, 20.00, 20.00, 25.00); диапазон [10.00, 20.00] — ровно 4 товара; (а) с `Sort.by("price")` обе страницы по 2 элемента, вместе — все 4 id (порядок пар не гарантирован); (б) с `Sort.by("price").and(Sort.by("id"))` — p0 = пара 10.00 по id, p1 = пара 20.00 по id (точные ассерты), повторный запрос той же страницы возвращает тот же состав; в комментарии: при сортировке только по цене СУБД не обязана сохранять порядок равных элементов — элемент может «перескочить» на соседнюю страницу или потеряться; правило: последним ключом сортировки — уникальный (id).
- Подсказка (не решение): стабильная пагинация = сортировка, в которой нет двух «неразличимых» строк.
