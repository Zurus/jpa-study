# Задание 08. Нестабильный порядок: тай-брейк по уникальному ключу
- Тема: Пагинация (Page / Slice / Pageable / Sort)
- Difficulty: 8
- Что нужно сделать: Тест создан заранее (TASK08Test): 4 товара с ценами [10, 10, 20, 20] (равные пары). Страницы `size = 2` запрашиваются с сортировкой (а) только по цене и (б) по цене + id. Вариант (б) даёт ТОЧНО детерминированное разбиение (проверяется точный порядок id и повторным вызовом); для варианта (а) в комментарии зафиксирован риск: элементы с равным ключом могут «прыгать» между страницами между запросами. Методы в репозиторий добавлять не нужно.
- Стартовый код:
```java
// Тест создан заранее: com.example.jpalab.tasks.t08.TASK08Test
// (а) Sort.by("price"): p0, p1 — разбиение пар НЕ гарантировано (проверяются только
//     безопасные свойства: размер страниц и покрытие всеми 4 id)
// (б) Sort.by("price").and(Sort.by("id")):
//     p0 = [i1, i2] (цены 10), p1 = [i3, i4] (цены 20) — строго, по точным id
//     повторный запрос той же страницы возвращает тот же состав
```
- Тест для проверки:
```bash
mvn -Dtest=com.example.jpalab.tasks.t08.TASK08Test#uniqueTieBreakerMakesPagingDeterministic
```
- Критерий приёмки: Тест: с составным сортированием `(price, id)` обе страницы имеют точный ожидаемый состав (id-ы ассертами); повторный запрос той же страницы возвращает тот же состав (детерминизм зафиксирован двойным вызовом); в комментарии: при сортировке только по цене СУБД не обязана сохранять порядок равных элементов — при повторных запросах (и особенно при вставках/удалениях) элемент может «перескочить» на соседнюю страницу или потеряться; правило: последним ключом сортировки — уникальный (id).
- Подсказка (не решение): стабильная пагинация = сортировка, в которой нет двух «неразличимых» строк.
