# Задание 10. N+1 в сервисной логике (реальная транзакция)
- Тема: N+1 и стратегии загрузки (JOIN FETCH / @EntityGraph / batch fetching)
- Difficulty: 10
- Что нужно сделать: Тест создан заранее (TASK10Test) в реальной транзакции (`@SpringBootTest` + `TransactionTemplate`): «сервисный» сценарий — загрузить список товаров и для каждого собрать строку `"<name> [<categoryName>]"`. Сначала сценарий выполняется «наивно» (`findAll` + цикл по `getCategory`), затем тот же сценарий через fetch join-метод `findAllWithCategoryFetched` (уже существующий пример в репозитории). SQL посчитаны, выигрыш зафиксирован. Методы в репозиторий добавлять не нужно.
- Стартовый код:
```java
// Тест создан заранее: com.example.jpalab.tasks.t07.TASK10Test
// setup (своя транзакция): 5 товаров / 5 категорий; commit
// фаза «наивно»:  inTx { stats.clear(); findAll(); цикл "name [category]" }  -> 6 SQL (1 + 5)
// фаза fetch:     inTx { stats.clear(); findAllWithCategoryFetched(); цикл } -> 1 SQL
// строки из обеих фаз одинаковые
```
- Тест для проверки:
```bash
mvn -Dtest=com.example.jpalab.tasks.t07.TASK10Test#serviceScenarioNaiveVsFetch
```
- Критерий приёмки: Тест: наивный сценарий в реальной транзакции — 6 prepared statement (1 SELECT по товарам + 5 по категориям), fetch join-сценарий — 1; собранные строки `"<name> [<categoryName>]"` в обеих фазах совпадают; в комментарии зафиксировано: в сервисном коде выбор fetch-стратегии — вопрос производительности на каждую страницу/список, а не «оптимизация для галочки».
